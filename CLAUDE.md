## Code Comments

* Use comments only when they provide useful context that is not obvious from the code.
* Comments should explain **why** something is done, not simply repeat **what** the code does.
* Comment complex business logic, unusual decisions, temporary workarounds, and important limitations.
* Do not add comments to straightforward components, styling, variable assignments, or clearly named functions.
* Keep comments short, accurate, and updated whenever the related code changes.
* Prefer clear variable and function names over unnecessary comments.

## Commit Messages

* When asked to create a commit, use a short and simple commit message.
* Write commit messages in lowercase using the imperative form.
* Use the format: `<action> <feature or change>`.
* Do not use long, overly detailed, or multi-line commit messages.

Examples:

* `add route protection`
* `add game detail page`
* `fix login redirect`
* `update game cards`
* `remove mock data`
* `refactor profile form`
